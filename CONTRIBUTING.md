# Contributing

Provider terms change often, and corrections are the most useful contribution. A link to the provider's own page that shows the change is enough.

## Reporting a change

Open an issue with:

- the provider and the page in this repo that is wrong or out of date
- a link to the official source (documentation, terms, privacy policy or announcement)
- the date you checked it

## Pull requests

- Change one provider or topic per pull request where you can.
- Cite the official source for every claim, in the page's Sources list, with the date you accessed it.
- Update the page's "Last checked" date and, if the summary changed, its row in the README table.
- Test any commands or code you add.

## Where things live

- `README.md`: the overview, the quick-answer table and the index. Keep it short.
- `providers/<provider>.md`: one page per provider. Start with the header line (link back to the README, last-checked date, web version link) and end with the footer, as the existing pages do.
- `docs/<topic>.md`: topics that span providers, such as compliance, verification and architecture.

## Style

- Plain, direct sentences. Say what the provider does, what it doesn't, and how to check.
- Quote or paraphrase the provider closely. If the provider's page doesn't say something, write that, rather than guessing.
- No marketing language, and no em dashes.
